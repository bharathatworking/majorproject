# NLI calibration set

There are two levels:

- **Paragraph level** (`paragraph-items.jsonl`, `npm run calibrate-meaning`): chooses every meaning threshold: `SIM_MIN`, `ENTAILMENT_MIN` and the NLI paragraph rule. It is described first, below.
- **Sentence level** (`pairs.jsonl`, `npm run calibrate-nli`): the original set, which chose the premise strategy and `NLI_CONTRADICTION_AGG`. It is described after the paragraph-level section.

## Paragraph level: `npm run calibrate-meaning`

```powershell
npm run fetch-models                                  # the NLI model, once
ollama pull all-minilm                                # similarity is part of the rule
npm run export-labels                                 # labels.csv: the real outputs, blind, random order
npm run import-labels                                 # your my_label column → paragraph-items.jsonl (-- --dry-run to check)
npm run calibrate-meaning -- --reviewed-only          # choose on dev, report on test
npm run calibrate-meaning -- --verbose                # every item's scores
npm run calibrate-meaning -- --json scores.json       # write every item's scores
```

### Items

`paragraph-items.jsonl` holds one simplified paragraph per item, judged against its original in `paragraphs.jsonl` (67 originals):

- **67 real outputs.** One verbatim `qwen2.5:3b` simplification of each original, made with the app's own `buildPrompt` (default adult profile, target grade 6, one attempt, no meaning retry). The originals came in three batches: 15 from the sentence-level set, 5 added in round 1 and 47 in round 2. Simplifications missing from `paragraphs.jsonl` are generated by `node scripts/make-paragraph-items.mjs`, which also stores each original's glossary `hintedWords`. `node scripts/add-paragraph-items.mjs` then adds the missing `#real` items.
- **20 copies with one injected error each** (round 1), 4 per type: `number` (a changed number or date), `negation`, `name` (a swapped name), `dropped-fact` (a key fact removed), `added-claim` (a claim the original doesn't make). Each copy is its real output with exactly one edit, shown in `note`. Copies are unfaithful by construction, so they are labelled automatically (`label: "unfaithful"`, `reviewed: true`).
- **Dev and test halves,** by paragraph (a real output and its copy always share a half), balanced per source. **Thresholds are chosen on dev only;** test is only reported.

| Field | Meaning |
|---|---|
| `id` | `<paragraphId>#real` or `<paragraphId>#<errorType>` |
| `paragraphId` | The original in `paragraphs.jsonl` |
| `split` | `dev` or `test` |
| `origin` | `qwen2.5:3b` (verbatim) or `injected` |
| `injectedFrom` | For copies, the real item it was made from |
| `simplified` | The simplified paragraph (the model's raw output, bullets included) |
| `label` | `faithful` or `unfaithful`: yours for real outputs (from `labels.csv`), automatic for copies |
| `labelNote` | Your note from `labels.csv` |

### How to label (blind)

1. Run `npm run export-labels`. It writes `labels.csv` with one row per real output (`id, original, simplified, my_label, note`), in random order, without any proposed label. It never overwrites a CSV that already has labels.
2. Open it in Excel or LibreOffice (UTF-8). In `my_label` write `faithful` or `unfaithful` (`f` / `u` also work); `note` is optional. Leave `my_label` empty to skip a row.
3. Run `npm run import-labels` (`-- --dry-run` first to check). An unknown value stops the import and names the row.
4. Run `npm run calibrate-meaning -- --reviewed-only`.

**The standard (decided 2026-10-15).** A paragraph is **faithful** when every statement in it is supported by the original and no key fact is changed or dropped. A dropped name, number or date makes it **unfaithful** only when it is a **key fact**: one needed to answer who / what / when / where / how many about the paragraph's main point. Minor, incidental names may be dropped. A changed, contradicted or added fact is always unfaithful.

### How an item is judged (the extension's rule)

Since 2026-10-15 (round 2), a simplified sentence of fewer than 7 words, or one starting with This / That / It / These / They, is scored together with the previous simplified sentence (`hypothesisFor` in `nli.ts`). The sentence-level set (`pairs.jsonl`) scores single hypotheses without a previous sentence, so this rule doesn't apply there.

An item **passes** at a setting when all of these hold:

- SBERT cosine (all-minilm, original vs the plain output) ≥ `SIM_MIN`.
- The entity rule passes (`entityVerdict`): the share of the original's entities kept is ≥ `ENTITY_RECALL_MIN`, and every number, date and time zone of the main claim is kept. The main claim is the original sentence closest to the whole paragraph by all-minilm, or every sentence of a 1–2 sentence original. Matching is `detectEntities` + `findMissingEntities`, value-based for numbers and dates.
- The NLI paragraph rule passes (`nliVerdict` over the sentence scores of the app's own `checkEntailment`):
  - Rule A: every non-exempt sentence has entailment ≥ `ENTAILMENT_MIN`.
  - Rule B: the same, except that one neutral sentence is tolerated when there are 6 or more.
  - Under both rules, no sentence may have contradiction above `CONTRADICTION_MAX` (0.2).

False-fail = failed faithful / faithful. Catch = failed unfaithful / unfaithful. Paired catch is the injected copies that fail while their real output passes, which is a cleaner view of whether the injected error itself was noticed.

The grid on dev covers `SIM_MIN` 0.60–0.95 (step 0.01) × `ENTAILMENT_MIN` 0.05–0.95 (step 0.05) × rule {A, B} × `ENTITY_RECALL_MIN` {1, 0.9, 0.8, 0.75, 0.67, 0.5}. It keeps the settings with false-fail ≤ 10% and catch ≥ 90%. Ties are broken by, in order:

1. lowest false-fail;
2. highest catch;
3. rule A;
4. the strictest entity recall;
5. the setting nearest the centre of the remaining plateau.

The script then prints both rates on dev and on test, with Wilson 95% intervals.

## Files

There are 12 Wikipedia lead paragraphs (CC BY-SA 4.0, pinned revision) and 3 U.S. government instruction or list texts (public domain). `text` is the original. `simplification` is a real `qwen2.5:3b` output for it, made through local Ollama on 2026-10-15 with the app's own `buildPrompt` (adult profile, target grade 6, no rolling context, default sampling).   | `id` | Unique item id |
  | `paragraphId` | The `paragraphs.jsonl` id |

## How to review

For each line of `pairs.jsonl`:

1. Read the paragraph (`paragraphs.jsonl`, same `paragraphId`) and the `hypothesis`.
2. If the proposed label is right, set `"reviewed": true`.
3. If it is wrong, add `"label": "faithful"` or `"label": "wrong"` (and fix `errorType`), then set `"reviewed": true`. Don't edit `proposedLabel`, so the change stays visible.
4. Run `npm run calibrate-nli -- --reviewed-only`.

## How an item is scored

These are the extension's rules (`src/lib/quality/premises.ts`, `nli.ts`):

1. The premises are the paragraph's sentences plus every window of 2 adjacent sentences. They're ranked by all-minilm cosine to the hypothesis, and the top 3 are scored.
2. Entailment is the max over those 3.
3. Contradiction is the max (`'max'`) or the best-entailing premise's (`'best-entailing'`).
4. An item **fails** when entailment < t or contradiction > `CONTRADICTION_MAX` (0.2).
5. **False-fail rate** = failed faithful / faithful. **Catch rate** = failed wrong / wrong.
6. The target is the highest t in 0.30 to 0.70 with false-fail ≤ 10% and catch ≥ 90%.

The script also prints these rows for comparison:

- "all premises": no pruning.
- "before": the old strategy, with the whole paragraph as the only premise.
- Truncated pairs (over 512 tokens) before and after.
- A one-thread CPU timing proxy per simplified paragraph.
